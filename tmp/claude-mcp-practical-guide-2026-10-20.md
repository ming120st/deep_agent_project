# Claude MCP 사용 실무 가이드: 연결 권한, 도입 절차 및 보안 운영

- **기준일:** 2026-10-20
- **조사 기준:** Anthropic Claude Code MCP 문서, Model Context Protocol(MCP) 소개 및 사양, MCP 공식 Tools·Security Best Practices·Authorization 문서
- **유의:** 실제 설정 키, 지원 전송 방식, 권한 모델 및 동작은 사용하는 Claude 제품·클라이언트·MCP 서버 버전에 따라 달라질 수 있으므로 배포 전 해당 버전의 공식 문서를 확인해야 합니다.

## 핵심 요약

MCP(Model Context Protocol)는 AI 애플리케이션이 외부 도구, 데이터 소스, 서비스와 표준 방식으로 연결될 수 있도록 하는 프로토콜입니다.

실무적으로 MCP 연결은 단순한 플러그인 추가가 아니라, **외부 시스템의 조회·변경·실행 권한을 Claude 워크플로우에 추가하는 일**로 다루는 것이 적절합니다. 따라서 연결 대상과 목적을 먼저 정의하고, 검증된 서버만 사용하며, 최소 권한으로 시작해야 합니다.

권장 흐름은 다음과 같습니다.

1. 업무 목적과 필요한 데이터·작업 범위를 정의한다.
2. 출처와 유지관리 상태가 확인된 MCP 서버를 선정한다.
3. 전용 계정·제한된 토큰·최소 권한으로 연결한다.
4. 읽기 전용 도구부터 연결하고 결과를 검증한다.
5. 쓰기·삭제·배포 등 영향이 있는 작업은 사용자 또는 운영자의 명시적 승인 절차를 둔다.
6. 호출 로그, 권한 변경, 토큰 만료·폐기를 지속적으로 관리한다.

## 실무 도입 절차

### 1. 목적과 허용 작업을 먼저 정의

- 해결하려는 업무 문제와 기대 효과
- 연결할 시스템 및 데이터 분류
- Claude가 수행해도 되는 작업과 수행하면 안 되는 작업
- 읽기, 생성, 수정, 삭제, 실행, 배포 등 작업 유형별 위험도
- 사용자 승인 또는 관리자 승인이 필요한 작업
- 책임자, 운영 담당자, 장애·오남용 대응 절차

### 2. 검증된 MCP 서버 선정

- 공식 제공자 또는 조직이 검토·승인한 저장소인지 확인
- 소스 코드, 배포 패키지, 릴리스 이력, 유지관리 상태 확인
- 서버가 제공하는 도구와 각 도구의 입력·출력·부작용 문서화 여부 확인
- 인증 정보와 민감 데이터 처리 방식, 네트워크 통신 대상, 로그 정책 검토
- 출처가 불명확하거나 필요 이상의 권한을 요구하는 서버는 운영 환경에 바로 연결하지 않음

### 3. 최소 권한 계정과 토큰으로 연결

- 업무별·환경별로 계정과 토큰을 분리
- 필요한 API 범위(scope)만 부여
- 가능하면 읽기 전용 권한으로 시작
- 운영 환경과 개발·검증 환경의 자격 증명을 분리
- 토큰 만료일, 회전 주기, 폐기 절차를 정의
- 토큰을 설정 파일, 소스 코드, 프롬프트, 로그에 평문으로 남기지 않음

### 4. 읽기 전용 검증부터 시작

초기 연결에서는 조회·검색·상태 확인처럼 되돌릴 필요가 적은 작업부터 검증합니다.

- Claude가 의도한 도구만 선택하는지 확인
- 도구 입력값이 예상 범위를 벗어나지 않는지 확인
- 반환 데이터에 민감정보가 과도하게 포함되지 않는지 확인
- 오류 상황에서 권한 상승이나 우회 동작이 발생하지 않는지 확인
- 호출 기록을 추적할 수 있는지 확인
- 외부 콘텐츠의 지시가 도구 호출에 부당한 영향을 주지 않도록 프롬프트 인젝션 위험 검토

### 5. 쓰기·삭제·실행 작업은 승인 기반으로 설계

1. Claude가 실행 계획과 예상 영향을 제시한다.
2. 사람이 대상, 변경 내용, 권한, 되돌리기 방법을 확인한다.
3. 사용자가 명시적으로 승인한다.
4. 승인된 범위 안에서만 도구를 실행한다.
5. 실행 결과와 변경 식별자를 기록한다.
6. 실패 또는 예상 밖 결과가 발생하면 중단·복구 절차를 수행한다.

### 6. 운영 모니터링과 정기 재검토

- MCP 서버 등록·변경·삭제 이력
- 도구 호출 이력과 오류 현황
- 쓰기 작업의 승인 기록
- 토큰 발급·회전·만료·폐기 상태
- 권한 범위와 서비스 계정 목록
- 서버 및 의존성의 보안 업데이트
- 비정상 호출, 과도한 호출, 예상 밖의 데이터 접근 탐지
- 사고 발생 시 토큰 폐기, 서버 연결 해제, 영향 분석 절차

## 설정 예시

> 아래 예시는 MCP 서버 연결 구조를 설명하기 위한 **개념 예시**입니다. 실제 Claude Code 설정 파일 위치, JSON 필드명, 명령어, 전송 방식, 환경 변수 처리 방식은 제품 및 버전에 따라 달라질 수 있습니다.

```json
{
  "mcpServers": {
    "internal-docs-readonly": {
      "command": "example-mcp-server",
      "args": ["--mode", "readonly"],
      "env": {
        "API_BASE_URL": "https://api.example.internal"
      }
    }
  }
}
```

- 서버 이름은 용도와 권한 수준이 드러나도록 지정합니다. 예: `internal-docs-readonly`
- 읽기 전용 모드가 지원된다면 초기 검증 단계에서 우선 사용합니다.
- 인증 토큰 등 비밀값은 설정 파일에 직접 넣지 않고 안전한 비밀 관리 방식으로 주입합니다.
- 실행 명령과 인수는 승인된 패키지·경로인지 확인합니다.
- 업무 목적과 무관한 도구는 노출 또는 사용하지 않도록 제한합니다.
- 개발·검증·운영 환경은 서버 주소와 자격 증명을 분리합니다.

## 보안·운영 체크리스트

### 도입 전

- [ ] 업무 목적과 허용 작업 범위를 문서화했다.
- [ ] 연결 대상 시스템의 데이터 민감도와 영향도를 분류했다.
- [ ] MCP 서버의 출처, 유지관리 상태, 배포 방식, 제공 도구를 검토했다.
- [ ] 서버가 요구하는 네트워크 접근과 인증 범위를 확인했다.
- [ ] 개발·검증 환경에서 먼저 테스트할 계획을 수립했다.
- [ ] 고위험 작업의 승인 절차를 정의했다.

### 설정 시

- [ ] 개인 관리자 계정 대신 전용 서비스 계정 또는 제한된 계정을 사용했다.
- [ ] 최소 권한과 최소 범위의 API scope만 부여했다.
- [ ] 읽기 전용 권한 또는 읽기 전용 도구부터 활성화했다.
- [ ] 운영·개발·검증 환경의 토큰과 설정을 분리했다.
- [ ] 토큰·비밀번호·API 키를 코드, 설정 파일, 프롬프트, 로그에 평문으로 저장하지 않았다.
- [ ] 토큰 만료, 회전, 철회 정책을 적용했다.

### 운영 중

- [ ] 도구 호출, 오류, 승인, 권한 변경을 추적할 수 있다.
- [ ] 쓰기 작업 전에 대상과 예상 영향을 사용자에게 보여주고 승인받는다.
- [ ] 민감정보가 도구 결과나 대화 맥락에 과도하게 노출되지 않도록 점검한다.
- [ ] 외부 문서·웹페이지·이메일 등의 지시를 신뢰하지 않고 프롬프트 인젝션 위험을 검토한다.
- [ ] 불필요해진 서버 연결, 계정, 토큰을 즉시 비활성화하거나 폐기한다.
